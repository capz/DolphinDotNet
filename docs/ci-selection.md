# CI selection

Pull requests run checks selected by `scripts/ci_changes.py` from the complete
three-dot diff between the PR base and head. This is deliberately cumulative:
a documentation commit on a PR that also changes the runtime still tests the
runtime. We do not assume an earlier commit's checks validated the current tree.

| Changed area | Selected jobs |
|---|---|
| `docs/`, README, security policy, license only | Selection tests and final CI result |
| `tests/DebuggerTests/` only | Host GDB protocol |
| Debugger library or acceptance probe | Host GDB protocol, GameCube DOL, Dolphin boot |
| Dolphin smoke/protocol scripts or their unit tests | GameCube DOL, Dolphin boot |
| IDE launch probe or build-workflow test only | IDE workflow on all three platforms |
| Compiler, SDK, managed libraries, samples, assets/build tools | Managed compiler, IDE workflow, GameCube DOL, Dolphin boot |
| Native source, headers, vendor code, Makefiles | Managed compiler, IDE workflow, portable runtime, GameCube DOL, Dolphin boot |
| Workflow, selector, unknown paths, other tests/scripts | All checks |

Rules combine when multiple areas change. Removed files count, and moves are
compared without rename detection so both old and new paths select their checks.
If comparison data is missing or invalid, all checks run. Main-branch pushes and
manual workflow runs always run the full suite, including release prerequisites.

Dolphin consumes fresh GameCube artifacts from the same workflow run. We do not
reuse previously passing artifacts to skip target builds. Individual steps within
the large managed/native jobs remain together because many consume temporary
files generated by earlier steps; splitting them needs explicit artifact and
fixture boundaries first.

The workflow always runs the selector and a final `CI result` check. The latter succeeds only
when every selected job succeeds and every unselected job is skipped. It fails
for selected failures, cancellations, unexpected skips, or detector failures.
Existing job names remain unchanged. `CI result` can be made the required check
in repository branch protection; this implementation does not change protection
settings.

For successful `main` pushes and manual runs, the release job gathers
sample DOL artifacts **already built** by `gamecube` and `gamecube-extra`.
It publishes **one** `DolphinDotNet-samples.zip` release asset containing
`<Sample>.dol` for each normally built sample. Build-only and emulator
acceptance fixtures are excluded. Staging and packaging do not compile any
additional samples. When a new sample starts producing a native DOL in the
normal jobs, add that existing output to the staging mapping and release
verification list.

Run selector regression tests with:

```sh
python3 -m unittest discover -s tests -p test_ci_changes.py
```

Extend filters conservatively when adding components. Include all consumers,
shared compiler/runtime dependencies, and producer jobs needed for artifacts.
