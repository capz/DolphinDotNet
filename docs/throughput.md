# Native asset throughput and cooperative frame waits

AssetStream keeps ReadAtAsync and its single-outstanding-read rule. Native reads are enabled by default; UseNativeReads=false retains the chunked managed comparison path. Each instance owns separate read handles for the two paths, closed after outstanding work retires. The comparison workspace remains allocated to support mode switching.

The service executor launches one logical read into a generation-checked, exclusively leased native buffer. It suspends its managed context and releases the execution gate during bounded backend reads. All public storage bridges wait before entering shared filesystem/handle state while native I/O is active. This deliberately serializes backend storage access rather than assuming FAT/disc internals are thread-safe. It removes per-chunk application publication/copy steps, but uses the existing service executor rather than a new pool of OS threads. A logical read produces one application completion. Cancellation is observed after native I/O retires; it does not abort an OS read in progress. Buffer Dispose retains memory while leased; other buffer operations reject the busy range. Raw borrowed addresses remain subject to the normal caller ownership contract.

Scheduler.PollStride controls how many AOT block polls share one clock check. Default 64; 1 retains legacy cadence. GC polling placement is unchanged, and the slower path retains the existing 1 ms clock deadline. Large stride values may increase task service latency; use measured workloads rather than assuming faster is universally better. PollCalls/SlowPollCalls expose diagnostics. Application/background callback queues now use a FIFO ring instead of shifting a list on every dequeue.

Scheduler.ProductiveWaits is opt-in. End-frame GPU/VSync waits suspend the application context and release the managed gate, allowing the background executor to progress. Application continuations still cannot reenter an active render frame. The gate and application context are restored before frame retirement. EndFrame remains synchronous and current fence semantics remain valid. This is not asynchronous GPU submission or a new framebuffer pipeline.

Draw2D skips native trigonometric calls for zero rotation. Renderer exposes a caller-scratch Mesh[] batch overload over the existing native implementation; all meshes must share full material state and transform, with native count/range checks retained.

Tests: asset_native_test verifies positional bytes, short reads/EOF, exclusive access and Dispose during an active lease. throughput_runtime_test verifies background progress during app waits, context restoration and stride behavior. Existing native tests remain part of make test. Cross-project acceptance must additionally exercise managed Tasks, frame ownership, audio, collisions and rendering under native I/O.

Deliberately deferred: asynchronous GPU fences/frame queues, removing begin-frame clear/copy synchronization, CFG-based GC-poll relocation, and a two-buffer SDK read pipeline. They change ownership/memory contracts and require separate measurements. The first two can no longer be justified merely by labeling all present time recoverable idle time.

## Legacy mode retirement

`AssetStream.UseNativeReads=false` is a temporary A/B validation fallback scheduled for removal once performance validation is complete and native reads are established as the performant way forward. Retain it while repeated Dolphin and hardware comparisons are still needed; the current emulator improvement alone does not close that validation.

The removal gate is repeatable throughput/frame-time improvement under representative budgets and storage backends, with preserved selected-detail readiness, actor/streaming progress, audio and memory bounds, and passing short-read, error, cancellation and disposal/lifetime checks. Record the decision and supporting measurements before deleting the fallback.

Once that gate is met, remove the selector, legacy FileStream handle, 8 KiB managed staging allocation and chunked Step/Publish path together. Update Hypercube's legacy comparison cases and telemetry/report expectations, retain the recorded before/after measurements, and keep native-path correctness and performance regression coverage. No fallback is removed by this tracking change.

## Follow-up: completion-aware waits and aligned reads

`Scheduler.CompletionAwareWaits` defaults to true. Task.Wait/GetResult first services application callbacks, rechecks the task under the managed execution gate, and parks only while it remains pending. This avoids sleeping after completion/cancellation/fault delivery during service. No AOT scheduler yield occurs between the check and park in the Core facade. Setting false retains the previous progress-and-unconditional-park comparison path until performance validation completes.

`Scheduler.DeadlineWaits` defaults to true. The timer pump publishes its earliest actionable monotonic deadline. Timed waits shorten their 1 ms timeout when the deadline is nearer; already due timers yield once per hint to the service executor, then retain a timed backstop if service cannot advance (for example during native I/O). The 1 ms upper bound remains for network polling, cancellation and stale timer hints. Queued/executing callbacks are excluded from deadline selection, and timer removal clears a stale hint. This does not move managed timer callbacks onto a native thread or permit application reentry during a graphics frame.

`AssetStream.NativeReadQuantum` defaults to 32768. Accepted settings are 16384, 32768, 65536 and 0 (the previous bounce-only comparison). A destination aligned to 32 bytes with at least 32 bytes remaining is read directly with a cache-line-multiple count capped by that quantum. Unaligned prefixes and short tails use the existing aligned bounce buffer. Short reads re-evaluate alignment; interrupted reads retry; EOF/error/lease/disposal contracts remain unchanged. Quanta bound each backend call, not the duration of an entire logical request. Cancellation still retires after that request. The single native storage lane and managed execution gate ownership rules remain unchanged.

`Scheduler.WaitStat(index)` reports the calling executor's cumulative counters: 0 compatibility-progress calls, 1 parks, 2 park elapsed microseconds (including gate reacquisition), 3 maximum park microseconds, 4 explicit service calls, 5 service microseconds, 6 deadline-shortened parks, 7 avoided parks after completion, 8 maximum timer due-to-service lateness (reported on the application executor). `ResetWaitStats()` resets application counters and timer lateness. Productive GPU/VSync waits are not included in park counters. No runtime-wide gate-wait attribution is claimed.

`AssetStream.ReadStat(index)` reports completed logical requests: 0 backend calls including interrupted/error/EOF attempts, 1 returned bytes, 2 bounce-copy bytes, 3 direct bytes, 4 logical requests, 5 backend microseconds, 6 maximum backend request microseconds. Backend time starts immediately before gate release and ends before gate reacquisition; it includes scheduling/native-read overhead. Counters are accumulated only after reacquiring the gate to avoid torn 64-bit snapshots on PowerPC. `ResetReadStats()` starts a new completion window; requests finishing afterward count in that window even if launched earlier.

The follow-up validation suite records these counters alongside frame time, detail readiness and transfers. Legacy read retirement still requires the performance/correctness gate above. The new false/zero comparison controls can be removed with their old paths after the corresponding validation decision; they are not intended as permanent independent backends.

`CopyWaitStats(long[9])` and `CopyReadStats(long[7])` copy a consistent counter group in one native bridge call under the gate. Use these for reports: separate scalar reads in application code may be separated by AOT safepoints and observe different completions. Short/null/wrong-element snapshot buffers are rejected.

`Scheduler.ApplicationTimers` defaults to true. The generated dispatcher polls timers on either executor under the existing managed gate, so a native read occupying the service executor no longer prevents the application from observing due delays. Timer callbacks still post to their captured executor, and graphics critical sections still prevent application service/reentry during rendering. False retains the previous background-only timer pump for profiling. This specifically addresses read/timer head-of-line blocking; it does not add parallel managed mutators.
